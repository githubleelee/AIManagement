# 爱管理（AI Management）

新一代 AI 驱动的软件项目管理平台。以「透明、协同、数据驱动」为核心理念，构建**需求 → 任务 → 进度 → 质量 → 风险 → AI 建议**的一体化管理闭环。

软件项目管理课程项目 · 4 名团队成员 + 多 AI 智能体（4+n）· **当前发布版本 v1.0.0**

> **⚠ AI 能力边界（请先读这条，再看功能）**：本版的"AI 驱动"指 **AI 出建议 + 人工确认后生效**，不指模型能力本身。具体：① AI 需求拆解的执行器是**本地确定性 Stub**（无 SDK、无外部网络请求，页面已标注）；② AI 排期在**未配置真实模型时显式失败**（`AI_SERVICE_UNAVAILABLE`，不静默回退本地桩）；③ **尚未接入真实大模型**，也未做真实厂商模型验收。完整边界见第五节「发布边界」与 [Release Notes](docs/release-notes-v1.0.0.md)。

---

## 一、这个产品解决什么

我们观察到三个真实痛点，并分别给出产品化的回答：

1. **排期靠拍脑袋** → 任务带计划起止与 **FS 前置依赖**，甘特图统一时间轴；**前置未"验收关闭"时后继不允许开工**（服务端校验，不是提示）。
2. **进度不透明、"做完"与"验收通过"混为一谈** → 六状态任务机（未开始/进行中/卡住/暂停/待验收/已验收），**提交由负责人做、关闭由验收人做**，验收人是任务字段且**不得与负责人相同**；仪表盘、成员负载、看板、甘特共用同一套口径。
3. **AI 生成的东西没人敢用** → AI 只产出**建议**，必须由 PM 人工处置（采纳 / 修改后采纳 / 拒绝）才写入正式数据；每次处置**写审计**；执行器与数据边界在页面上如实标注。

## 二、快速开始

> **全新 clone 必须从「首次运行」开始。** `.env` 与 `*.db` 都在 `.gitignore` 里，新 clone 两者都不存在；
> 跳过「创建 `.env`」与「应用迁移」的典型症状是**服务能起来、`/health` 也正常，但任何走数据库的接口都返回 500**。

### 首次运行（新 clone 必做，按顺序执行）

```bash
# 1. 安装依赖（postinstall 会自动执行 prisma generate）
npm install

# 2. 创建本地环境变量文件
#    缺它的报错：Environment variable not found: DATABASE_URL
#    Windows PowerShell 用：Copy-Item .env.example .env
cp .env.example .env

# 3. 建库并应用迁移（SQLite 文件：src/db/dev.db）
#    缺它的报错：The table main.Project does not exist in the current database
npm run db:migrate

# 4. 写入演示账号与演示项目（幂等，可重复执行）
#    仓库没有注册端点，浏览器登录必须先有账号，故本步不可省
npm run db:seed
```

### 日常命令

```bash
npm run dev        # 同时启动后端（http://localhost:3000）与前端（http://localhost:5173）
npm test           # 全量回归（Vitest + supertest）
npm run typecheck  # 前后端类型检查
npm run build      # 产出 dist/
npm start          # 运行已构建的后端
```

浏览器打开 **http://localhost:5173**（用 `localhost`，Vite 绑的是这个名字）。后端健康检查：`GET http://localhost:3000/health` 返回 `{"status":"ok"}`。

## 四、质量与验证

```bash
npm run typecheck                 # 期望：两端均 0 错误
npm test                          # 期望：105 个测试文件 / 2077 用例通过 / 0 失败
npx vitest run src/modules/ai-scheduling/integration.pending.test.ts
                                  # 期望：12 passed（US-12 的 12 条验收门禁，含 1 条真实浏览器走查）
```

- 全量测试**每个文件使用独立临时 SQLite 库**，测试之间互不污染；测试数据一律由工厂函数自建。
- 唯一测试 seam 是 **HTTP 接口层**：越权用例必须打接口，不允许用"前端不渲染按钮"代替。
- US-12 的 12 条门禁包含：真实 HTTP + 真实临时 SQLite + 真实回环模型服务，以及一条**真实浏览器走查**（登录→页面生成→页面改日期→复核→采纳→审计→**刷新后仍持久**）。其中浏览器门禁依赖本机 Chrome 与 `playwright-core`；缺依赖时**会打印警告并跳过**（如需强制失败，设 `US12_REQUIRE_BROWSER=1`）。
- 并行跑全量的并发上限在 `vitest.config.ts`（`maxWorkers: 8`）：默认按 CPU 数起 worker 会让共用一个 SQLite 文件的并发写偶发 `database is locked` 伪失败。

## 五、发布边界（如实声明）

**已发布并验证**：上表"已发布"的全部模块；全量回归通过；端到端主旅程与异常/权限旅程均已实跑通过（US-12 门禁的完整记录见 `docs/ai-records/A/issue-32/A-I32-20261024-gates.md`，端到端旅程的过程截图与数据库读数见课程交付物证据目录）。

**明确未做（已登记在 `docs/product-backlog.md`）**：
1. **US-13 AI 质量/进度/风险/效率分析**：只有纯函数与测试，无端点、无页面、无消费方。
2. **@提及通知（`task.mentioned`）**：需新建 Mention 数据模型，属后置项，不计入本版 AC。
3. **UML 详情端点的计时型侧信道**（PB-07 第 ⑤ 项）：响应体已与"不存在"逐字一致，仅延迟不同，保留为已知非阻断项。
4. **真实 AI 供应商**：本版**不配置**供应商/模型/密钥（教学项目定位）。AI 排期在未配置时**显式不可用**，绝不静默退回本地桩；AI 需求拆解使用本地确定性 Stub，页面已如实标注。
5. **CI 流水线**：未搭建。质量门禁由本地全量回归 + 类型检查 + 代码冻结标签承担。

## 六、部署 / 运行注意

1. **不要把 `NODE_ENV` 设为 `test`**：会关闭通知的 10 秒定时扫描，逾期/节点类通知不再产生（能力如实降级）。
2. **`var/uploads/`（附件实体）不得注册为公开静态目录**；下载只走带鉴权的 `GET /attachments/:attachmentId/download`。
3. **外部 AI 边界**：仅允许普通虚构演示数据；禁止外发真实密码 / token / 密钥 / 真实个人信息；敏感对象默认不进上下文。
4. 首版未做多环境配置分离，`PORT` 与 `DATABASE_URL` 通过 `.env` 控制（见 `.env.example`）。

## 八、工作约定（沿用团队协议）

- **接口契约冻结**：任何修改走「提出 → 受影响模块确认 → 单人修改 → 通知全员」。
- **文件所有权**：`src/shared/*`、`src/db/schema.prisma`、`src/routes.ts`、`src/app.ts`、`src/modules/authz/permissions.ts`、前端骨架为**单写区**，由指定唯一修改人改动。
- **测试纪律**：不为通过而减少断言或改跳过；门禁用例不得用桩替换真实端口/鉴权/事务。
- **改口径必须留痕**：口径变更写入 `DECISIONS.md`，并同步受影响的测试、文案与设计文档。
