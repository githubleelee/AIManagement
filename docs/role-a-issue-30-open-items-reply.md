## 一、本次新批复

### 1. 成员能否流转风险状态（原未决）

- **MEMBER**：可流转**自己负责**（`Risk.ownerUserId` = 本人）的风险状态，含重开；不得流转他人负责的风险（403）。
- **PM**：可流转**全部**风险状态，含重开。
- **VIEWER**：一律 403（只读）。
- 非项目成员 / outsider：404（不泄漏项目存在性）。
- 判定仍走统一入口 `can()`，不在业务代码私写角色判断；对象归属以库中真实 `projectId` / `ownerUserId` 为准，不信任请求体自报。

### 2. 关闭阻断是否允许强制关闭（原未决）

- **不允许强制关闭**：存在未 `CLOSED` 任务或未处理 / 处理中（`OPEN` / `IN_PROGRESS`）风险时，关闭请求**拒绝**并返回 **409 CONFLICT + 阻断清单**。
- 重开项目：**仅 PM**；重开同样不绕过既有校验。
- 关闭 / 重开入口放**本票自己的模块**，不改 `src/modules/project/`。

### 3. 关闭端点路径命名（原未决）

- **接受你提的 `/projects/:projectId/close`**，handler 在本票模块内，落在项目命名空间但不占用项目模块的实现。
- 若 B 在 `src/routes.ts` 登记时发现命名冲突或需要统一前缀，由 B 与你确认后再定，不因此阻塞实现。

### 4. 风险变更是否写审计（原未决）

- **要写**：风险的新增、编辑、状态流转（含重开）与项目关闭动作均写 `AuditLog`（沿用既有表），至少含操作者、动作、对象类型 / ID、变更前后与时间。
- 理由：报告第 11 节要求风险闭环可追溯，13.1 要求「关键状态变更可追溯」；`AuditLog` 已在既有模块中用于同类留痕，不需要新表。
- 注意：AI 建议的存储**不**走 `AuditLog`（见 `DECISIONS.md` `ai.suggestion-store-shared`），两件事不要混。

### 5. 枚举线上取值（记录口径，由你的 Zod 落地）

| 字段 | 取值 |
|---|---|
| `Risk.level` | `HIGH` / `MEDIUM` / `LOW`（界面：高 / 中 / 低） |
| `Risk.status` | `OPEN` / `IN_PROGRESS` / `RESOLVED` / `CLOSED`（界面：未处理 / 处理中 / 已解决 / 已关闭） |
| `Project.status` | `ACTIVE` / `CLOSED`（不进共享 `ProjectView`，由本票端点返回） |

### 6. 健康度阈值表述对齐（避免实现偏差）

- 我们的口径是 **偏差 = 计划时间进度 − 实际进度**（落后为正），阈值 ≤10pp 健康 / 10–25pp 预警 / >25pp 风险，与 `DECISIONS.md` `analytics.health-thresholds-and-planned-progress` 一致。
- 你在 #30 / #24 写的「-10% / -25%」是同一含义的相反符号表述，请按上述方向实现并在响应里返回 basis，**以 DECISIONS 条目为准**。
