# AI 交互记录指南（每会话独立文件版）

> **状态**：本轮**新增**的记录指南，**供团队确认启用**；启用时间由负责人填写并同步既有规则后生效。
> 启用时间：`____-__-__ __:__`（时区 `____`）　负责人：`________`
>
> **边界声明**
>
> - 本指南是**开发/实验过程中使用 AI 的过程材料**，用于教学与自我追溯；**不是**产品需求 US11-13 的运行时 AI 审计实现。
> - 本指南**不授权迁移历史**：既有 `docs/ai-interaction-log.md`（表 5）**不删除、不修改、不重排、不补造**。历史仍按旧规则呈现实时、只追加原貌，**不得声称旧规则已改完**。
> - 变更对象仅限"启用后新发生的交互"；团队确认启用前，不放宽、不替代任何既有规则。
> - 团队确认启用后，需以**新增说明或单独团队约定**记录新旧规则的适用边界，不改写旧条目，避免两套规则并存冲突。

## 1. 记录模型

启用后每条记录 = **四件套**：

1. **七列表 5 摘要**：沿用旧列（序号 / 时间 / AI 智能体角色 / 任务场景 / 人类输入摘要 / AI 输出要点 / 团队处置及理由），只写摘要，不复制完整 prompt 与生成代码。
2. **每会话原始可见输入输出附件**：真实导出并留存。**只留存可见回复与工具结果**，**不索求隐藏思维链**。
3. **真实验证证据**：实测命令、实际工作目录、结果或失败、未测项，及验收截图（相对路径）。
4. **汇总索引**：由单一负责人维护，指向各独立记录文件与其源路径/原序号。

> **序号 vs ID**：旧表 5 用全局连续序号；新方案用**稳定 ID** 标识文件，文件内部再维护**本地会话序号**。汇总导出时可临时连续编号，但**不得因此改写 ID、源路径或历史原序号**。

## 2. 目录与命名

- 建议目录：`docs/ai-records/<角色>/issue-<编号>/`
  - 主记录：`<ID>.md`（一文件一会话）
  - `raw/`：原始导出（工具自带 MD / JSONL / TXT 等）
  - `evidence/`：验证输出、截图等
  - 示例路径：`docs/ai-records/B/issue-25/B-I25-20261017-coder01-01.md`
- **记录 ID**：`角色-Issue编号-日期-agent唯一名-会话序号`
  - 命名示例（**仅为命名示例，不是实际交互**）：`B-I25-20261017-coder01-01`
- **唯一写者**：每个文件只有一个实际归档者；文件内**互动序号**从 1 递增。同一成员、同日、同 agent 名下的**会话号**递增，不能覆盖已有文件。
- **主控与子 agent 独立**：主控与每个子 agent 各自独立文件、独立序号，不得混记或冒充对方。只读 agent 由主控按 §4 当次归档并标明来源。
- **agent 唯一名**：跨并行会话**不可重用**，否则会撞名；负责人**提前分配会话号**。
- **无工单的实验准备任务**：使用固定主题代号（如 `PREP`），**不得虚构 Issue 编号**。

附件的文件命名建议（与主记录 ID 对齐，避免同名覆盖）：

| 位置 | 命名建议 | 说明 |
|---|---|---|
| `raw/` | `<ID>-<导出类型>.<ext>` | 如 `<ID>-tool-export.jsonl`、`<ID>-chat.txt` |
| `evidence/` | `<ID>-<日期>-<用途>.<ext>` | 如 `<ID>-20261017-test.txt`、`<ID>-20261017-accept.png` |

## 4. 实时记录时机

- 必记的**关键交互**：任务下达、方案调整、代码产出、测试失败与修复、审查、人工确认。
- 每个任务**至少一条**；任务较大时就地记录多个关键节点，**不是只写最后一条**。
- **新记录待确认时不得冒充人工采纳**；人工确认后**追加新行或复核小节**，关联原 ID 与序号，**不覆盖旧结论**。
- 子 agent 收到的**主控指令不得冒充人类直输**；「人类输入摘要」列可注明"主控下发"并**链接回人类原任务**。
- **只读 agent 不为写日志而破只读**：由其主控在当次归档返回内容，注明**原 agent + 实际归档者**；**不允许事后臆造**。

## 5. 原始导出

- 优先使用工具自带的 MD / JSONL / TXT 导出，**保持原有顺序与实际时间**。
- 拿不到原始记录时，**明确写出缺口**（缺什么、为何缺），**不补造**。
- **不猜**模型、时间、测试结果；**建议命令 ≠ 已执行命令**，须区分标注。
- 原始导出**当时**登记本地路径 / ID 并及时保存；**不要只留 `/tmp` 等易丢链接**。
- 测试记录须写：实际命令、实际工作目录、结果或失败、**未测项**；验收截图用**相对链接**。

证据条目建议逐条写清（可直接复制）：

```text
命令：<实际执行的完整命令>
工作目录：<实际 cwd>
结果：<通过 / 失败 + 关键输出；或「未执行」>
说明：<建议但未执行的命令单独标注，勿当作已执行>
```

## 6. 安全与脱敏

- 原始导出**先审查脱敏再放公共仓库**；token / password / 真实数据 / `.env` / 数据库 / 私有报告**不得上传**。
- 脱敏件须**标注替换位置与原因**；**不把脱敏版说成"无删节"**。
- 确需原件时**受控保存**，且**不作为外发 AI 输入**；公共仓库只留教学/脱敏信息。

## 7. 汇总与索引

- **不让 4 人共写旧表 5**：新记录采用独立文件，避免全局编号冲突。
- 新索引由**单一负责人维护/汇总导出**；当前**无自动脚本**，不得声称"已有自动导出"。
- 导出可**连续展示序号**，但必须**保留稳定 ID 与源路径/原序号**，**不得重排或改写历史**。
- 本节规则均为**启用后**约定，**需团队确认**。

## 8. AI 开工附加提示词（可复制）

```text
记录要求（本次会话）：
1) 按 docs/ai-interaction-recording-guide.md 模板，实时写入/追加独立记录文件，不批量补写。
2) 不伪造人工确认：待确认即标注待确认，人工确认后追加新行/复核小节并关联原 ID 与序号。
3) 不越只读：只读 agent 不写日志，由主控当次归档并注明原 agent 与实际归档者。
4) 敏感信息不落公共仓库：先审查脱敏，标注替换位置与原因，不把脱敏版说成无删节。
5) 不自行修改旧表 5 与共享索引；索引只由指定负责人维护。
6) 结束时给出归档证据清单：记录 ID、文件路径、原始导出路径、验证证据路径、未测/缺口项。
```

## 9. 提交前自检（Checklist）

- [ ] 元信息齐全：ID、角色、负责人、时间及时区、基线 commit、指令来源与父会话 ID 已填。
- [ ] 摘要区分"原文/证据"：人类输入与 AI 输出均有原始附件对应，未复制完整 prompt 与代码。
- [ ] 人工 review 状态正确：待确认/采纳/修改后采纳/拒绝明确，未冒充人工采纳。
- [ ] 已脱敏：无 token / password / 真实数据 / `.env` / DB，替换位置与原因已标注。
- [ ] 路径有效：raw/ 与 evidence/ 相对链接可打开，未只留 `/tmp` 链接。
- [ ] 唯一路径：ID 与文件路径本会话唯一，agent 唯一名未与其他并行会话撞名。
- [ ] 未碰历史：未改旧表 5、未改共享索引、未重排历史。
