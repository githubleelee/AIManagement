# 前端可用性检查流程（Sprint 1 · US-01 / US-02 / US-03 / US-05）

| 项目 | 内容 |
|---|---|
| 用途 | 从**前端界面**出发，对 Sprint 1 四个用户故事做可用性走查，产出可复核的证据 |
| 对照基线 | `爱管理_Sprint1基线_US-01_02_03_05(1).md`（AC 与 §2.6 演示脚本） |
| 行为权威 | `docs/sprint1-spec-interface-contract.md` |
| 前端路由约定 | `docs/frontend-routes.md` |
| 执行前提 | 检查对象是**当前工作区源码**（含 `feat/sprint1-wrapup` 的任务前端实现）。若只跑 `main`，`/projects/:id/tasks` 仍是占位页，本流程第 C/D 层会大面积失败——先确认分支 |
| 维护方式 | 与 `docs/sprint1-current-status.md` 同规则：变更走「提出 → 确认 → 单人修改 → 通知」 |

> **一句话口径**：本流程只判「**用户在浏览器里能不能看到、看懂、走通**」。真正的「服务端强制校验 / 越权拒绝」必须另经 API 层取证（见 §6），前端隐藏按钮**不算**权限通过（基线 R4）。

## 1. 分层模型（先记住检查分五层，别跳层）

| 层 | 名称 | 回答的问题 | 主要手段 |
|---|---|---|---|
| A | 可达性 | 页面能不能打开、深链/刷新/回跳是否正确 | 地址栏直达、F5、清除登录态 |
| B | 主链路 | 按 §2.6 演示脚本能不能一次走通 | 四账号手工走查 |
| C | 角色与越权 | 三种项目角色界面入口是否正确收放 | 切换登录账号 |
| D | 反例与边界 | 非法输入/约束冲突时有没有明确反馈 | 故意输入非法值 |
| E | 可用性与无障碍 | 错误态/空态/加载态、键盘、窄屏是否可用 | DevTools 设备模拟 + 键盘 |

**顺序**：A → B（先证能走通）→ C → D → E。任何一层出现「页面白屏 / 控制台报错 / 数据串号」，**先停下修，不要继续往下记**——后面的结论都会失效。

## 6. 反例与接口层取证（前端隐藏 ≠ 通过，基线 R4）

以下必须用 DevTools Network 或 `curl` 确认**服务端**真的拒绝。以 `curl` 为例（先登录拿 token）：

```bash
# 1) 登录取 token
curl -s -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"account\":\"member1\",\"password\":\"Passw0rd!\"}"

# 2) 用该 token 调 PM 专用写接口（应 403），并核对响应体不含对象字段
curl -i -X POST http://localhost:3000/projects/<projectId>/goals \
  -H "Authorization: Bearer <member1-token>" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"越权尝试\"}"
```

| # | 反例 | 期望状态码 / 码 | 期望响应体 |
|---|---|---|---|
| R1 | Member 调用「添加成员」 | 403 `FORBIDDEN` | 不含项目数据 |
| R2 | Member 调用「创建业务目标/用户故事」 | 403 `FORBIDDEN` | 不含对象字段 |
| R3 | Member 调用「创建任务」 | 403 `FORBIDDEN` | 不含对象字段 |
| R4 | 非成员（`outsider`）访问项目/需求/任务任一端点 | 404 `NOT_FOUND` | **无任何对象字段**（不泄漏存在性） |
| R5 | 未授权成员直连敏感故事/任务 ID | 404 `NOT_FOUND` | 与「对象不存在」响应**逐字一致**，不含「无权限/敏感」字样 |
| R6 | 验收人=负责人（创建与编辑两条路径） | 422 `ACCEPTOR_EQUALS_OWNER` | details 指 `acceptorUserId` |
| R7 | 项目仅 1 名成员时建任务 | 422 `INSUFFICIENT_MEMBERS` | — |
| R8 | 负责人/验收人传非本项目成员 | 422 `NOT_PROJECT_MEMBER` | — |
| R9 | 计划结束早于开始 | 422 `END_BEFORE_START` | — |
| R10 | 删除仍有子项的目标/活动/故事 | 409 `HAS_CHILDREN` | details 带 `goalId`/`activityId`/`storyId` |

> 判定原则（契约 I-3 / I-4）：**404 用于「对象不可见」**（不泄漏存在性），**403 用于「对象可见但操作不允许」**。若越权返回 200 或回显了对象内容，直接记**阻断缺陷**。

## 7. E 层 · 可用性与无障碍（沿用 `docs/frontend-audit-2026-09-25.md`，需复核现状）

审查清单（F01–F09）可能已部分修复，**逐条在当前工作区复核**，不要直接抄结论：

| 编号 | 检查点 | 期望 |
|---|---|---|
| E1 | 加载失败 vs 空数据 | 两者**互斥**：失败显示错误+重试，空数据才显示空态，不并存 |
| E2 | 非 404 错误 | 网络/5xx 不得误报「项目不存在或无权访问」，应有「加载失败 + 重试」 |
| E3 | 删除/移除 | 有二次确认（`ConfirmDialog`），请求期间禁用重复提交 |
| E4 | 表单字段错误 | 失焦或提交后**就近**显示具体原因；不要只禁用按钮而不说原因 |
| E5 | 可访问名称 | 行内角色/状态下拉带 `aria-label`（如「修改张工的角色」） |
| E6 | 标题层级 | 页面级空态用 `<h1>`，列表空态用合适级别 |
| E7 | 窄屏 | 320px/375px 视口下侧栏不挤爆内容、宽表可横向滚动 |
| E8 | 键盘 | 仅键盘可完成登录→建项目→建任务→删除确认；焦点可见 |
| E9 | 控制台 | 主链路上**无未捕获异常/红色报错** |
