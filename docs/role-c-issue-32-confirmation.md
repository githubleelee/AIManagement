## 9. 重复 / 并发确认、失败回滚与应用 / 审计一致性规则

- **整份原子应用**：同一 DB 事务内复核 snapshot / 权限 / 业务约束，批量计划写、处置及成功审计一次完成；**任一失败则全部不改，不部分成功**。
- **模型调用在事务外**：不得用逐条 HTTP PATCH 伪装原子。
- **幂等**：相同请求重复提交返回已有结果，不重复写、不重复发事件。
- **唯一最终处置**：一份建议只允许一个最终处置；并发或不同内容再次处置返回**冲突**。
- **重试鉴权**：每次重试先鉴权，不得借幂等越权。
- **失败留痕**：失败 / timeout / 权限拒绝另记必要的失败记录或安全日志，**不当采纳成功**，不泄漏 payload / 密钥，**不与已回滚的成功事务混淆**。
- **可追溯**：AI 建议与 PM 人工修改 / 理由 / 审核人 / 最终应用结果可追溯。

生成与应用分为两个阶段：

- **生成阶段**：鉴权后在数据库写事务外调用模型，保存建议、输入快照与生成记录，交 PM 预览。
- **确认阶段**：应用 PM 正在审核的那份已保存建议或其允许的日期修改；**不重新调用模型生成另一份建议**。

确认应用的受控路径：

1. 鉴权（含撤权即时收敛），识别本次处置请求与已保存建议；
2. 开启同一 DB 事务，复核最终处置状态、snapshot / 权限 / 业务约束；
3. 批量写计划、写处置与成功审计；
4. 任一失败整体回滚，另记失败 / 安全日志，不显示部分成功。
