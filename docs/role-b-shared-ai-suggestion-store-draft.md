> **状态：DRAFT · 未冻结 · 未落表。** 本文只做**字段与语义草稿**，供 ROLE-D（#31 公共 AI 框架）、ROLE-C（#32 AI 排期）、ROLE-A（#33 AI 分析）三方对齐。

## 1. 目标与不做什么

**目标**：一套存储同时支撑「AI 生成建议 → 人工处置 → 可统计采纳质量」的闭环，供 #32（排期建议）与 #33（质量 / 进度 / 风险 / 效率分析）复用，避免两套建议表导致采纳率、拒绝原因、模型版本等统计分叉。

**不做**：

- 不为 #32 / #33 各建一套表；
- 不用 `AuditLog` 承载建议（它没有「待处置」状态、输入快照、模型版本与处置结论）；
- 不代 A / C 实现分析逻辑、排期 workflow、采纳应用与统计；
- 不在 D 的 #31 字段提案到位前落表或写迁移；
- 不把敏感对象内容写入建议载荷（沿用「敏感默认不入上下文」）。

## 2. 候选字段（待 D 提案与 A / C 需求合并后定稿）

> 命名均为**候选**；D 的 #31 提案为准，本文只保证字段**覆盖范围**不缺失。

### 2.1 归属与场景

| 字段（候选） | 说明 |
|---|---|
| `id` | 主键 |
| `projectId` | 归属项目（项目隔离边界） |
| `scene` | 场景标识：`scheduling`（#32）/ `insights`（#33）；更细的 `analysisType`（质量 / 进度 / 风险 / 效率）由 #33 定义 |
| `requestId` | 一次生成请求的标识（同一请求重试可关联） |
| `createdByUserId` | 触发人生成（当前为 PM-only） |

### 2.2 输入范围与快照（可追溯基线）

| 字段（候选） | 说明 |
|---|---|
| `inputScope` | 输入范围：参与对象类型 / id 集合或筛选条件（**不含敏感对象**） |
| `snapshot` | 关键数据快照：任务日期 / 状态 / 负责人、成员、依赖、里程碑、参与负载范围、有效权限（#32 已在 `scheduling.advice-snapshot-transaction-idempotency` 冻结；#33 复用同一语义） |
| `fingerprint` | 快照摘要（分量与算法待 #46 与 D 对齐；**B 不擅定 hash 字段**） |
| `aiPopulation` | 实际参与 AI 的对象数（排敏感后的子集；不得冒充全项目基数） |

### 2.3 生成记录

| 字段（候选） | 说明 |
|---|---|
| `mode` | `stub` / `api`（桩与真实 API 必须可辨识） |
| `modelId` / `modelVersion` | 模型标识与实际可得版本；取不到记「未提供」，**不得猜测** |
| `generatedAt` | 生成时间（ISO 8601 UTC wire；业务日期口径 `Asia/Shanghai`） |
| `generationStatus` | 成功 / 失败 / 超时；失败只留必要失败或安全证据，不写敏感内容 |
| `suggestion` | 建议内容（结构化载荷；**不含敏感正文**） |
| `error` | 失败原因（如有；不含密钥 / payload） |

### 2.4 人工处置

| 字段（候选） | 说明 |
|---|---|
| `disposition` | `ACCEPT` / `ACCEPT_MODIFIED` / `REJECT`（唯一最终处置） |
| `disposedByUserId` | 处置人（仅 PM；`permissions.ai-suggestion-disposal`） |
| `disposedAt` | 处置时间 |
| `modification` | 修改后采纳时的实际改动（#32 限 `TODO` 任务的 `planStart` / `planEnd`；#33 由 A 定义，如「转为正式风险记录」的引用） |
| `reason` | 理由（拒绝 / 修改时必填，服务端校验） |

### 2.5 应用结果与关联

| 字段（候选） | 说明 |
|---|---|
| `appliedAt` | 应用时间；未应用（拒绝）为空 |
| `appliedResult` | 应用结果（写入的对象 / 字段摘要、成功或回滚结论） |
| `linkedRiskId` | #33「风险预警建议 → 人工确认 → 转为正式风险记录」的关联（可选） |
| `linkedTaskIds` | #32 应用涉及的任务（可选，便于回查） |

### 2.6 约束与索引（候选）

- 一份建议**只允许一个最终处置**（唯一约束或 CAS；具体机制以 #46 为准）；
- `@@index([projectId, scene, generatedAt])`、`@@index([projectId, disposition])`；
- 相同请求重试返回已有结果，不重复写、不重复发事件（#32 已冻结；#33 沿用）；
- 处置与应用在**同一事务**内完成（#32 已冻结；#33 若涉及写入正式数据同样适用）。

## 3. 权限与可见性

- **生成**：PM-only（#32 已确认）；#33 同口径由 `permissions.ai-suggestion-disposal` 与既有汇总口径覆盖；
- **处置**（采纳 / 修改后采纳 / 拒绝）：**仅 PM**，MEMBER / VIEWER 只读；#32 与 #33 **共用同一个 Action**，由 B 在共享存储落地时随统一 `can()` 加入；
- **查看**：PM 全项目；MEMBER / VIEWER 只能看到自己有权看到的正式计划 / 分析结果，**不得借建议或审计入口越权**；
- 未登录 401、对象不可见或外项目 404、可见无操作权 403；
- 每次请求与每次处置 / 重试都重新鉴权，撤权即时收敛。
