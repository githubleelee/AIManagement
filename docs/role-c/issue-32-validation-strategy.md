## 1. 目标与结论边界

分别验证三个等级，不混为“已完成 US-12”：

- L1 当前独立版本：规则计算正确、虚构预览交互正常、正式按钮禁用、不访问项目 API/模型、不写正式计划。
- L2 main 兼容候选：本域文件叠加到固定的最新 main 后，类型/构建通过、不破坏既有权限、任务、验收、甘特/负载及普通页面。
- L3 正式功能：公共契约、共享建议存储、鉴权、写窗口和挂载交付后，验证真实生成/保存/审核/原子应用/审计。当前不能通过 L3。

“无冲突”包括路径/文本、类型、权限、业务语义、DB/事务和团队写锁六类。测试能发现并降低风险，不能保证未来 main 任意变动后永远无冲突。任何结论必须绑定 main SHA、候选文件清单及内容摘要。

## 3. G0：保护现场与建立可复现候选（先做，失败即停止）

1. 记录 HEAD/main SHA、tracked diff、逐文件未跟踪清单、git status；读取测试辅助代码/数据库配置逻辑，只看源码，不读取 .env、现有 DB 或私有资料。
2. 对本票允许文件逐项建立 manifest（相对路径、SHA-256），白名单限 src/modules/ai-scheduling/、web/src/pages/scheduling/ 和明确审过的本域文档。所有未提交的本票源文件都要保护，不能只 git stash 默认参数，也不能 git add .。
3. 执行 `git fetch origin main`，固定 M 为该次 SHA；先检查 M 的 tracked 路径与 manifest 是否有同路径冲突。路径已被别人占用就人工核对，不能直接覆盖。另比较 M 与开发 HEAD 的 schema、authz、task、shared、注册/前端骨架变化。
4. 在全新、唯一临时目录用 `git worktree add --detach <candidate> <M>` 建候选；复制白名单文件并校验摘要。原工作树不 reset/clean/stash/rebase，不自动移动开发分支；主分支现有功能不在原地测试。
5. 在候选上检查相对 M 的完整改动（tracked diff + untracked manifest）。公共文件/旧 task/package/lockfile 不应出现本票改动；数据库、.env、node_modules、dist、密钥不得被复制或纳入发布。
6. 建同 SHA M 的对照环境，使用相同 Node/npm、依赖锁和虚构数据。对照也只用隔离 DB，不能使用开发 DB。用于区分 main 原有失败与本票引入失败。

放行：原现场未变、允许文件完整且摘要一致、无路径覆盖、无越权改公共区。此阶段不提交或推送。

## 5. G2：规则与输入安全矩阵

已有用例逐项核对覆盖；不足则在本域新增测试，不将以下计划标为已通过。

| 类别 | 必测输入 | 断言 |
|---|---|---|
| 日期 | 非法日/闰日、倒置、同日、月末/年末、上海 00:00 两侧 | 严格日期校验；新开始不得早于上海今天；自然日含起止 |
| 应用范围 | 六种状态逐个、越字段、重复任务、空调整、跨项目/敏感/不存在任务 | 仅 TODO 日期可改；拒绝信息不泄漏无权对象 |
| FS | 修改前置/后继/两者、未改邻接任务、跨子集端点、不可用、截断 | 至少次日；相关边不能被静默丢弃；不完整不能放行 |
| 分配 | 负责人/验收人退组、相同人员、成员不足 | 不合法整份阻断，不自动改人员 |
| 提示 | 同人日期重叠、结束推迟、越已有关联里程碑、无里程碑 | 仅已确认提示，不变成硬阻断；无关联不编造 |
| 数据隔离 | 任务/父故事敏感、隐藏边/计数、PM 全局与 AI 子集 | 外发白名单，无敏感正文/全局基数/隐藏占位；防御裁剪不代替查询鉴权 |
| 快照 | 日期/状态/成员/验收人/FS/关联/里程碑/负载范围变化，集合换序 | 相关变化不相等；纯排序不变化；比较函数不是锁 |
| 可用性 | 已知空、unavailable、truncated、未知完整性 | 显式区分；需要完整校验的正式应用 fail-closed |

当前候选数组型数据不一定已表达可用性/完整性、父故事敏感和角色快照；这是待补实现，测试应揭示缺口而不是靠 fixture 假定完整。必要时 L1 仅放行明确“来源完整的预览输入”，仍禁正式操作，不能以提示语替代 L3 安全校验。

## 6. G3：真实浏览器验证当前独立预览

在候选中启动 Vite，指定唯一空闲端口并确认实际 URL；不误连旧目录遗留服务。由 browser_goto/fill/click 执行，必要时用 eval 查 DOM/运行时、console 查异常、network 查真实请求。

1. 初始空态：没有样例数据自动出现；正式生成/确认/拒绝操作不可触发。
2. 显式载入虚构样例：fixture/stub 标识、范围、模型信息可见。
3. 编辑合法日期、倒置、早于今天、FS 冲突、重叠与里程碑提示：硬阻断与提示按已批准语义区分。
4. 模拟快照过期：禁正式应用、提示重生成，不悄悄换建议。
5. 项目切换/撤销访问：清除旧内容/日期修改/理由；恢复访问不能复活旧草稿。模拟状态不是统一鉴权验收。
6. 刷新/窄屏：布局可读、输入可操作、不出现运行时异常；刷新后没有虚构的已保存结果。
7. 监控 network：预览没有项目 `/api` 请求、外部模型请求或正式写操作；保留必要截图与脱敏控制台/请求证据。

浏览器禁用按钮只是 L1 边界，不当作服务端安全。不可用数据场景若当前预览未支持，明确列缺口，不用 JS 临时注入把功能伪装完成。

## 8. G5：真实功能集成门（依赖到齐后才能执行）

先取得可引用的契约/迁移/权限/装配/写锁交接；不要把设计确认当作运行时交付。

- 真 HTTP + 隔离真实 DB 验证 PM 全入口，MEMBER/VIEWER、outsider、未登录分别按 403/404/401；直接请求绕过 UI 也失败。
- 生成前后及保存前撤权、每次重试撤权；先统一鉴权才读回历史；不把不同项目 PM 当本项目 PM。
- AI 失败/超时/非法输出不静默切桩；stub/api 明确；普通虚构数据真实 API 出流与日志脱敏留证。无法证明的外发情况不得称合规通过。
- 先生成并持久化；确认只应用已保存建议/允许的人工日期差异，模型调用计数不增加。
- 两任务正常提交；第二任务校验/写入失败、成功审计失败均整份回滚；无最终成功处置；必要失败证据在回滚后另记。
- 并发同请求一次生效，异内容/异 actor 冲突；已成功重放不被自身日期更新误判过期，不重复事件；首次审核人不覆盖。
- 所有相关快照变化整份过期；截断/不可用不放行；仍使用同一事务内真实读取和统一规则。对真实竞态用并发屏障/故障注入验证，不只串行测试。
- 拒绝不改任务；过期后拒绝与失败后状态依据最终共享状态机测试，不自创语义。
- 提交成功但事件失败/重启丢失：计划仍已应用，事件恢复按冻结协议，不重改计划、不冒称 exactly-once。
- 浏览器生成→查看原始建议→编辑→审核→确认→刷新后持久化；任务/甘特日期一致；负载计数按状态口径可能保持不变；审计/记录可追溯。

放行：12 个 integration TODO 用真实场景实现并通过，不能改成 mock 绿灯；新安全/竞态矩阵通过；B 完成正式挂载后做 L3 浏览器。无依赖时结论只能是 L1/L2，不宣称 L3。
