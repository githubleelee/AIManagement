# #32 独立实现与接入提案（非冻结公共契约）

## 已完成的独立能力

- `src/modules/ai-scheduling/schemas.ts`：本域临时设计类型，严格只允许 taskId/planStart/planEnd 调整；真实自然日检查；复用 main 的任务状态 schema。
- `policy.ts`：无副作用日期规则、上海今天、非敏感输入裁剪、实际参与范围/负载标注、快照比较。**无 DB、无鉴权实现、无 AI 调用、无计划写入。**
- `policy.http.test.ts`：仅测试文件注册 `/_test/*` HTTP 适配器，外部行为检查规则，不对内部调用计数。没有向正式 app 注册路由；不是实际生成/确认/越权 AC 验收。
- `web/src/pages/scheduling/SchedulingPage.tsx`：独立组件，输入范围/模式/版本/建议、日期编辑与校验、提示/阻断、基线过期、生成/处置忙碌/失败交互、拒绝入口和理由输入。访问状态由父级统一鉴权适配，不在组件内判断项目角色。
- `preview.html` / `preview.tsx`：仅开发用多页面入口，无业务路由挂载，不导入正式 App。普通虚构样例显著标记，生成与正式处置禁用，不读取 storage/cookie/数据库或请求项目 API。

## 规则边界

依据用户提供的 2026-10-17 #32 confirmation：

- 仅 TODO 可改日期，新开始不能早于北京时间今天；自然日含起止，FS 后继开始严格晚于前置结束日。
- 日期倒置、非 TODO、越字段、FS 日期违反均阻断；原成员/验收独立性约束保留。
- 同负责人日期重叠、新结束晚于原计划、超过已有里程碑只提示。没有过载阈值，不编造里程碑。
- 负载计入 DONE、不计 CLOSED，展示范围是输入参与子集，不冒称 PM 全项目基数。
- 实际开工的前置 CLOSED 检查属于任务状态入口，不在本票纯日期预览中伪造状态写入。
- `sameSchedulingBaseline` 仅提供顺序稳定比较，忽略采集时间，比较 revision、任务日期/状态/负责人/验收人/敏感、成员、依赖、里程碑。**它不是事务锁**。revision 必须由授权适配器表征权限等相关变化；真实应用前必须在同一事务现查数据、现鉴权。
- 输入裁剪只是一层防御：数据适配器必须先用统一 `can/visibilityScope` 查询层授权，不能把本域过滤当权限入口。含不可用关联依赖时受控校验失败，不泄漏其 ID。
- 纯函数调用前必须按 schema 验证；日期模型拒绝未知字段，不静默剥离越权字段。

## 给 B/D 的最小接入需求

本地 `SchedulingSnapshot` / `SchedulingProposal` 是 **本域设计稿，不是 shared 公共端口**，不得据此自行注册或让 D 迁就未冻结类型。收到正式契约后通过适配或替换，禁止保留重复的权威类型。

需要的语义：

1. 当前项目及授权范围的计划任务、有效成员、FS、已关联里程碑、参与负载和权限 revision/snapshot；来源与生成时间可追溯。
2. AI 端口接收最小非敏感输入，返回建议日期、理由、mode、model/version（未知记未提供）、requestId、生成时间；失败/超时显式返回，不能静默回桩。
3. 生成与确认分离，确认必须引用已持久化建议，不能确认时再生成另一份。
4. UI `onGenerate` / `onDecide` 是组件依赖回调，不是已冻结 AI/后端接口。由适配层连接实际契约，所有回调均需服务端重鉴权；demo 模式拒绝调用。

### 端点语义提案（路径待 B/C 确认，不注册）

- 项目建议生成：统一鉴权→读取快照→事务外模型调用→保存建议/输入范围/生成审计。
- 项目建议列表/详情/审计：统一 PM-only、查询层范围过滤，不泄漏其他项目存在性。
- 处置：建议 ID + requestId + 采纳/修改后采纳/拒绝 + 可允许的日期修改与理由。
- 同请求返回同结果，但先重新鉴权；一建议一最终处置，不同内容再次处置冲突。
- 单一事务复核快照/权限/规则，批量写计划、处置和成功审计；任何失败全部回滚，必要失败日志单独记录且不包含敏感 payload。

### B 的公共改动提案（尚未执行）

- PM-only Actions 与建议对象范围落 shared/authz。
- 建议/审核表优先复用 #31 的规范，requestId 与建议最终处置由 DB 唯一约束兜底；字段/迁移由 B/D 冻结。
- 事务可用的计划应用端口共享声明、app 注入；C 实现领域业务，不跨模块调 service。
- 后端注册与具体 UI URL、导航/路由文档由 B 单写。导出组件为 `SchedulingPage`，无自建全局 Auth/Router。
