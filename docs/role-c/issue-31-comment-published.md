### 二、希望共享端口覆盖的能力（先确认语义，再定签名）

1. **生成调用**：输入经服务端授权和排敏的最小上下文；返回可区分的结构化输出/错误及 mode、模型、版本、请求关联。调用在 DB 写事务外，不绑定供应商 SDK。
2. **保存待确认建议**：模型结束后重新统一鉴权，以短事务保存可追溯记录。期间撤权不向调用者返回结果，也不登记为其可用待确认建议；必要失败/安全证据另记。
3. **按授权项目读取**：支持只解析 id/projectId 的最小归属元数据，之后经 can() 再取受保护正文/历史；接口须能配合调用方事务，不能为幂等重放先泄漏结果。
4. **事务内唯一处置**：支持传入同一个事务上下文，原子检查 pending/唯一最终处置并记结果，与 C 的任务批量日期写、成功审计同提交；不能端口自己提前 commit，也不能把存储实现交给 C 再造一套。
5. **重放/冲突区分**：先鉴权，再判断请求身份；同逻辑请求返回首次结果，不重复写计划、不重复发事件；不同请求已处置则冲突。
6. **失败可观察**：区分模型超时/错误、输出非法、来源过期、已处置冲突、数据不可用等语义；具体错误 code 与 B 的既有错误契约对齐。日志不包含密钥或敏感输入正文。

共享层负责存储/并发协议；C 负责排期合法性、来源复核和业务事务编排；D 不代写 C 业务，B 仍是公共文件唯一写者。端口参数的 tx 类型与序列化 DTO 分开，不把 DB 客户端送入模型。

### 三、C 建议的幂等身份（请 D/B 核对，不是既定字段）

- 为一次逻辑处置提供独立请求标识，网络重试保持不变。
- 作用域候选：项目＋建议＋actor＋请求标识，另存规范化内容摘要（处置类型、日期集合、理由）。
- 仍有权的同 actor/同标识/同内容返回首次结果；同标识异内容冲突。另一 PM 即使内容相同也不是同一请求；首次审核人不可覆盖。
- 共享存储以建议最终处置唯一约束＋pending CAS 保护并发；具体表/索引/字段由 D/B 提案，C 不自行修改 schema。

该建议比“只按 payload 摘要识别重放”更明确地区分重试与独立操作，不引入队列或新的全局基础设施。

### 四、请 D/B 回复的最小事项

- D：上述字段哪些已覆盖，哪些需补；给出最小生成和共享存储签名、模型版本不可得表示、错误与模式字段。
- B/D：事务上下文如何传递、唯一处置及请求身份怎样落到表/约束，避免确认时再调模型。
- B/D：快照过期与“拒绝”是否独立，失败后建议是否仍待确认；请明确状态机，不能把失败假装最终成功。
- D/C（涉及 #37）：提交后派发失败、进程退出丢失及恢复/去重如何处理；计划提交成功仍是成功，补发不得重复改任务。不默认新增 outbox，不承诺 exactly-once；具体签名和失败证据分工可单独分批对齐。
- B：#32 的生成/查看/审计仍 PM-only；共享 #33 的可见范围不应自动扩给 #32。共享 DTO/读端口需保留场景级权限校验，不能因共用一张表而放开全部记录。

C 在 #32 提交 B 数据七问/事务十二问的完整核对，在 #24 登记公共层边界；相关评论互链见文末。本条是字段与能力需求，不声称 D 没有私下实现，也不等待所有运行时都完成才进行设计冻结。
